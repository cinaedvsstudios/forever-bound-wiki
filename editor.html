    Capsanoto Guidebook

    1. What Capsanoto Is

    Capsanoto is a lightweight structured writing environment for lore-heavy writing, long-form worldbuilding, scripts, novels, pitch material, and narrative documents.

    It is human-writing-first, local-first, portable, and designed to avoid heavy database/wiki complexity. The goal is to help writers move quickly while still keeping large bodies of connected text organized.

    2. Why Capsanoto Exists

    Capsanoto exists because writers often need to retrieve, reuse, reshape, and organize text without breaking creative flow.

    It prioritizes fast editing, contextual right-click tools, reusable TCards, local autosave, readable downloads, and creative ownership of the files.

    3. Application Structure

    The intended hierarchy is:

    Application → Writing Room → Folder → Tab → File → TCard

    Application
    Capsanoto itself: the browser-based writing app.
    Writing Room
    The project/profile workspace for a story world or major writing project.
    Folder
    A large category inside a Writing Room, such as Characters, Locations, Items, Worldbuilding, or Episodes.
    Tab
    A grouping inside a folder, such as Main Characters, Recurring Characters, Season 1, Songs, or Lore Checks.
    File
    An individual writing document, such as Mel, Luca, Ironvale, Runestones, or Episode 01.
    TCard
    A Transclusion Card: a reusable synchronized text block.

    4. Writing Room / Filing Cabinet

    The Writing Room button opens the Filing Cabinet, the floating folder/tab/file manager.

    Folders, tabs, and files
    Folders contain tabs. Tabs contain files. Files are the documents you write in.
    Metadata
    File metadata such as type, ID, tags, and updated date lives in the Filing Cabinet metadata pill instead of cluttering the document body.
    Edit mode
    The pencil unlocks inline editing for Writing Room, folder, tab, file, and metadata text.
    Duplicate
    Creates a copy of a file for variants, rewrites, or experiments.
    Trash
    Deleted files move to Trash so they can be restored later.
    Deprecated versions
    Deprecated versions are preserved old versions of files. This language is reserved for old versions, retired files, snapshots, and preserved history.
    Locks and expansion
    Folder/tab lock icons mark containers that should stay open. The rail buttons can collapse all or expand all.
    Jump rail
    The right-side rail uses folder icons as jump points. Clicking one expands that folder and scrolls the Filing Cabinet to it.

    5. Top Bar and Status Box

    Capsanoto title/icon
    Shows the app identity. The title icon size can be adjusted in Settings → Design.
    Writing Room button
    Opens the Filing Cabinet.
    Dynamic status box
    The center status box is intentionally important. It explains hovered controls, selected text, cursor context, clicked objects, save/autosave status, and what buttons will do.
    Format menu
    Contains Bold, Italic, H1, H2, Normal Text, and List commands.
    Subnoto
    Current state: placeholder. It opens a placeholder window and will be defined later.
    Insert menu
    Contains table insertion, horizontal rule, image insertion, Emoji Spark, TCard tools, and emphasis boxes.
    Search
    Current state: placeholder for future context/fuzzy search.
    Help
    Opens this Guidebook.
    Settings
    Opens Design, Download, and support/reset tools.

    6. Right-Click Context Tools

    Capsanoto is designed around highlighting text and right-clicking it. The context menu should keep common editing actions close to the writing surface.

    Link Anchor
    Turns selected text into a direct section target.
    TCard
    Creates a Transclusion Card from selected text.
    Link
    Creates a normal hyperlink to a file, section, TCard reference, or external URL.
    Link Pill
    Creates a rounded visual hyperlink.
    Link Editor
    Edits an existing link target without recreating the visible text.
    Pill color/style editing
    Right-click an existing Link Pill to change its visual color styling.

    7. Links and Navigation

    Document links
    Files can be opened by URLs such as editor.html?doc=Character-Mel-Ameldra.
    Section links / Link Anchors
    Heading IDs create section routes such as editor.html?doc=Character-Mel-Ameldra#Runestones.
    External links
    Normal web URLs are supported.
    TCard references
    TCard targets can use supported references such as block:Item-Runestones or {{Item-Runestones}}.
    Link Pills
    Link Pills are rounded hyperlinks that visually stand out from normal text links.

    8. TCards / Transclusion Cards

    A TCard stores reusable text once and displays that same text wherever the TCard is referenced.

    Editing the source text updates all referenced instances. Formatting may be local to the current document, while the underlying source text remains synchronized.

    Syntax
    Current supported reference syntax includes {{Item-Runestones}}.
    TCard panel
    The TCards panel lets you create, edit, style, and insert reusable cards.
    Insert behavior
    Insert TCard places the reference at the saved cursor position.
    Inline edit
    Rendered TCards show an edit button on hover; clicking it opens that TCard in the side panel.
    Style controls
    TCard background, border, text color, heading color, and text size can be adjusted.
    Drag/move
    Rendered TCards can be dragged within the writing area.

    9. Tables, Emoji Spark, and Emphasis Boxes

    Tables
    Tables insert at the cursor, use rounded corners, can be dragged, and show inline table tools for row/column/color edits.
    Emoji Spark
    Opens a scrollable emoji grid. Click an emoji to insert it; right-click an emoji to search the grid by word.
    Emphasis boxes
    Wrap selected text in a bordered emphasis block that can be moved and styled.

    10. Document Editing and Autosave

    Document title
    The title field edits the current file title.
    Writing area
    The main editable page supports browser rich-text editing, headings, links, images, tables, TCards, and emphasis boxes.
    Autosave
    Changes save locally in the browser. The status box reports saving and autosaved states.
    Reset Local Save
    Settings → Help includes Reset Local Save, which clears the browser autosave and reloads starter content.

    11. Download and Backups

    Download builder
    Choose files and/or TCards, reorder them, and download selected pieces.
    Caps file
    Downloads structured JSON for Capsanoto/Caps workflows.
    TXT
    Downloads plain text.
    HTML
    Downloads a browser-readable HTML file.
    Word-compatible
    Downloads a Word-compatible .doc HTML document.
    Clean output
    Downloads should render cleanly and strip editor-only UI artifacts.

    PDF and DOCX clean export are planned/experimental, not complete current features.

    12. Design Settings

    Settings → Design controls system styling, global dialogue/button styling, Writing Room window styling, Settings window styling, and Help window styling.

    Recommended font stack: Inter, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif. This keeps the app local-first and avoids requiring an external font dependency. Courier New is reserved for code-like/monospace text.

    13. Planned / Experimental Workflow Systems

    Subnoto
    Placeholder. The workflow will be defined later.
    Context Search / fuzzy search
    Planned search tools for finding content across files, TCards, and metadata.
    Slash Commands
    Planned commands such as /dialogue, /scene, /song, /spell, /tba, /pill, and /tcard.
    Timeline Blocks
    Experimental year/date blocks that may gather linked events, scenes, and TCards.
    Hover Names / entity profiles
    Planned hover previews for characters, places, objects, and other named entities.
    Speech Profiles
    Planned voice/dialogue profile helpers.
    Paragraph deprecation / deprecated TCards
    Planned preserved-history workflow for smaller text units.
    PDF/DOCX clean export
    Planned export targets beyond the current Caps, TXT, HTML, and Word-compatible downloads.

    14. Technical Notes

    Code type
    Static HTML, CSS, and plain JavaScript. No framework build step is required.
    Main app file
    app.js handles state, events, autosave, routing, TCards, links, downloads, dialogs, Filing Cabinet behavior, table tools, emoji picker, and design settings.
    Styles
    styles.css controls the theme, layouts, panels, typography, and CSS variables.
    Starter files
    content/documents.json seeds first-run content. config/auth.json remains for future preview auth work.
    Local storage keys
    forever-bound-writing-room-v2 stores files/TCards, capsanoto-design-settings-v1 stores design settings, capsanoto-help-html-v1 stores edited Help text, and capsanoto-writing-room-layout-v1 stores Filing Cabinet panel position/size.
    Versioning rule
    Use v1 as the first version, then v1.1, v1.2, and so on for future updates.
