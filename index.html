    Capsanoto Guidebook

    What Capsanoto is

    Capsanoto is a structured writing environment for Forever Bound. It is not intended to become a database-heavy wiki app. Its job is to make human writing faster, clearer, more portable, and safer to keep offline.

    The app is written as a static frontend: HTML entry files, one plain JavaScript app file, JSON starter/config files, CSS styling, and browser localStorage for autosave. There is no backend database in this preview.

    Launch links and files

    Launcher / default entry
    index.html opens the Writing Room from the repo root or deployed site root.
    Direct word program
    editor.html opens the same Capsanoto word program directly.
    Alternate direct entry
    writing-room.html is another direct entry for the same Writing Room UI.
    Starter content
    content/documents.json seeds first-run files and TCards.
    Preview config
    config/auth.json contains the shared password config. The current preview opens without the password gate while auth is being reworked.

    Core architecture

    The intended structure from biggest to smallest is: Application → Writing Room → Folder → Tab → File → Transclusion Card (TCard).

    Application
    Capsanoto itself: the static browser word program.
    Writing Room
    A profile/container for a story world or major writing space, such as Forever Bound Writing Room.
    Folder
    A large filing-cabinet category inside a Writing Room, such as Characters, Locations, Items, Worldbuilding, or Episodes.
    Tab
    A nested grouping inside a folder, such as Main Characters, Recurring Characters, Season 1, Songs, or Lore Checks.
    File / Document
    An actual writing document, such as Mel, Luca, Ironvale, Runestones, or Episode 01.
    Transclusion Card / TCard
    A reusable structured writing card embedded inside files or reused in other places.

    Current preview behavior: files are stored as a flat local document list and visually grouped by tags. Persistent nested folders/tabs are planned but should remain lightweight UI-layer structure rather than a heavy backend database.

    Example hierarchy

    Application: Capsanoto

    Writing Room: Forever Bound Writing Room

    Folders: Characters, Locations, Items, Worldbuilding, Episodes

    Tabs: Main Characters, Recurring Characters, Season 1, Core Themes, Songs

    Files: Mel, Luca, Greta, Erik, Ironvale, Episode 01

    TCards inside files: Timeline & Setting, A Plot, B Plot, Notes, Songs, Lore Check

    Transclusion Cards / TCards

    TCards means Transclusion Cards. TCards are the primary modular content container system in Capsanoto.

    TCards replace the old split between sections, cards, canon blocks, and transclusion blocks. There is no separate “section vs card” distinction anymore: TCards are the section system.

    What TCards can do
    TCards can be collapsible, movable, reusable, embedded/transcluded in other files, and used to hold structured writing sections.
    Examples
    Timeline & Setting, A Plot, B Plot, Notes, Songs, TBA, IDEA, REWORK, LORE CHECK, SONG TODO, VOICE TODO.
    Transclusion
    Transclusion simply means embedding or referencing a TCard elsewhere. The same stored text displays identically anywhere the TCard is used, so shared information only needs to be updated once.
    Terminology
    “Transclusion Card” and “TCard” are interchangeable.

    Top bar controls

    Writing Room button
    Opens the floating filing-cabinet panel. Use it to browse grouped file cards, expand a card, open a file, or copy that file URL.
    New Document
    Creates a new file from the built-in template and adds it to the Writing Room.
    Document Settings
    Opens title and metadata/tag settings for the active file. Tags currently drive visual grouping in the Writing Room panel.
    Status bar
    Explains cursor location, selected text, hovered controls, links, Link Anchors, TCards, emphasis boxes, and save/autosave messages.
    Format menu
    Hover to reveal bold, italic, heading, paragraph, and list commands.
    Links menu
    Hover to create/edit/remove links, make Link Pills, or insert Link Anchors.
    Insert menu
    Hover to insert tables, images, emoji, TCards, or emphasis boxes.
    Help button
    Opens this guide and release notes.
    Settings button
    Opens design, download, and support cards.

    Renamed terms

    Link Editor
    New name for Link Smith. It edits existing hyperlink targets without recreating link text.
    Link Pill
    New name for Pill Gate. It is a hyperlink displayed as a rounded pill UI element, such as [Character], [Location], or [Timeline].
    Link Anchor
    New name for Anchor Rune. It is a standard document heading/bookmark anchor and URL target for direct section linking.
    TCard
    Replaces TCard as the reusable content system.
    Download
    New name for Archive Export. “Archive” is reserved for future lifecycle/version features such as deprecated rooms, locked versions, snapshots, or archived projects.

    Writing and editing

    Document title
    The large title field edits the current file title. Use Document Settings for metadata/tags instead of showing metadata in the document body.
    Writing area
    The main editable page supports rich text through browser editing commands, local autosave, pasted/typed content, TCards, links, and emphasis boxes.
    Autosave
    Changes save to browser localStorage. The status bar shows saving/autosaved messages.
    Reset Local Save
    In Settings → Help, this clears the browser autosave and reloads starter content.

    Links, Link Pills, and Link Anchors

    Document URLs
    Files can be opened by URLs like editor.html?doc=episode-01.
    Link Anchors
    Heading IDs create section routes like editor.html?doc=Character-Mel-Ameldra#Runestones.
    Path Link
    Creates a link to an external URL, another file, a Link Anchor, or a TCard reference.
    Link Pill
    Converts selected text or an existing link into a rounded visual pill link.
    Link Editor
    Edits a selected link target without rebuilding the link text.
    Link Breaker
    Removes the selected link while preserving its visible text.

    Slash commands

    Slash commands are planned as a major workflow system for instantly creating formatted structured blocks while writing. They should reduce friction and avoid excessive menus/modals.

    Planned examples include /dialogue, /scene, /song, /spell, /tba, /pill, and /tcard.

    TBA and drafting notes

    Special lightweight drafting TCards may exist for TBA, IDEA, REWORK, LORE CHECK, SONG TODO, and VOICE TODO. These are simple outlined/status cards for drafting workflow, not separate database systems.

    Timeline blocks

    Timeline Blocks are experimental secondary systems, not core architecture. A Timeline Block could be a year/date block such as [1422] that dynamically collects linked events, wars, births, deaths, story scenes, and linked TCards onto generated timeline pages.

    This should remain lightweight and optional until the core Writing Room, Folder, Tab, File, and TCard workflow is working well.

    Download and backups

    Download builder
    Choose files and/or TCards, reorder them, then download selected pieces.
    Caps file
    Downloads structured JSON for Capsanoto/Caps workflows.
    TXT
    Downloads plain text.
    HTML
    Downloads a browser-readable HTML file.
    Word
    Downloads a Word-compatible .doc HTML document.

    Design direction

    Capsanoto should prioritize speed, readability, portability, low complexity, local-first compatibility, simple JSON storage, offline capability, and low corruption risk.

    The app should enhance human writing workflow rather than becoming AI-first or database-heavy.

    Design settings

    Settings → Design controls button colors, borders, text colors, text size, background image, dialog colors, status bar colors, emphasis box colors, panel colors, label text, dynamic text, and scrollbar colors. Settings are saved under capsanoto-design-settings-v1 in browser storage.

    Technical notes

    Code type
    Static HTML, CSS, and plain JavaScript. No framework build step is required.
    Main app file
    app.js handles state, events, autosave, routing, TCards/transclusion behavior, links, downloads, dialogs, and design settings.
    Styles
    styles.css controls the Writing Room theme and CSS variables.
    Local storage keys
    forever-bound-writing-room-v2 stores files/TCards, and capsanoto-design-settings-v1 stores design settings.
